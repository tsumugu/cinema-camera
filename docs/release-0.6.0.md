# 0.6.0 — 永続的な写真保存

Android 15向け、versionCode 6。前版と同じデバッグ署名キー。

## 変更

取得したRAW/JPEGと、RAW現像メタデータ、回転、撮影時刻、フィルター設定をnoBackupFilesDir/pending-photosに保存。AtomicFileとファイル・ディレクトリ同期を使い、保管済み入力をActivityの寿命から切り離した。RAWとJPEGそれぞれを取得コールバック内で保管し、RAW+JPEGの片方だけ到着した状態で画面を離れた場合も、届いている入力は保管して処理へ渡す。

写真ごとのJobSchedulerジョブをsetPersisted(true)で登録。JobServiceがバックグラウンド処理の寿命とCPUの起動を管理する。現像用のEGLはプレビューから独立し、プロセス内のロックで1枚ずつ実行する。OSの停止要求は協調キャンセルし、元データを残してジョブを再試行する。失敗時も元データを削除せず指数バックオフ。

固定写真IDをJPEGファイル名に使用。MediaStoreの同じ未公開行を再利用して再実行時の重複を防止。JPEGを書いて同期し、IS_PENDING=0と非ゼロのファイルサイズを再照会して公開を確認後、完了状態を原子的に書き、それから元データを削除する。公開直後のプロセス終了は、次回処理で既存の公開済みファイルを照合して完了できる。

起動時と15分間隔の永続復旧ジョブで、入力保管からジョブ登録までの間にプロセスが終了した場合も再検出する。既存ジョブを不用意に上書きせず、実行中ジョブをキャンセルしない。上部の設定に「未保存の写真を再試行」を追加。保存エラーは「データ保管済み／自動再試行待ち」と表示。

## 適用範囲

ホーム移動、画面終了、履歴からの終了、通常のプロセス終了・端末再起動から復帰可能な設計。OSの省電力・ジョブ割り当てにより実行が遅れる場合がある。強制停止中は実行不可で、次回起動後に再開する。カメラから未取得のデータ、最初の保管自体に失敗したデータ、アプリのデータ消去・アンインストール・記憶装置の故障は復旧できない。容量不足は入力を保持して再試行。RAW単独に恒久的な現像非対応がある場合も入力を残し、対応修正を待てる。

新しい依存ライブラリ、通信権限、常時稼働サービスは追加していない。再起動後のジョブ用にRECEIVE_BOOT_COMPLETEDを追加。JobServiceはBIND_JOB_SERVICEで保護。

## ビルドと確認範囲

通信不要のSDKビルド。オフラインビルド補助を更新し、現行マニフェストのApplication、サービス、権限も既存ライブラリのマージ結果へ取り込む。ユーザーの指定に従いテスト・lint・実機動作検証は実施していない。中断・再起動時の実機検証は未完了で、保存完了を実測で保証した版ではない。
