# 0.7.0 — RAWハイライトの色処理

Android 15向け、versionCode 8。前版と同じデバッグ署名キー。

## 症状と調査

提供された夜景JPEGでは、看板と下部の明るい領域で赤・青が上限付近に達し、緑が相対的に低い画素が広く見られた。JPEGには現像経路を示すEXIFがなく、その撮影がRAW現像かJPEG代替かは断定できない。現像前RAWと同時JPEGも手元になく、元シーンの正確な色や飽和箇所は確認できない。

コードでは、センサー信号を黒白レベルで正規化し、WB・シェーディング・露出ブースト、色行列を適用した浮動小数点RGBをGPUへ渡していた。WB後にすぐ8bitへ落としてはいない。ただしセンサー飽和で失われたチャンネル比を扱わず、出力の負成分をチャンネル単位で0にし、輝度だけの肩処理・sRGB変換・ルックの後に各RGBを0〜1で切っていた。RAWの飽和を含む入力から、マゼンタのハイライトが生じ得る経路があった。

EV操作はCameraX CameraControlの露出補正で、自動露出へ作用する。現像時だけのEV調整ではない。中央タップはAFとAEで、EV=0でも中央付近を測光した自動露出の結果として看板等が飽和することはある。

## 修正

- BayerセルでWB適用前の最大センサー信号と、WB・シェーディング適用後のRGBおよび中立色の飽和限界を計算。RAWが飽和付近で、全カメラチャンネルが明るい領域に限って色行列後RGBを滑らかに中立色へ近づける。弱い色成分が残る明るい赤・青等の光源は、この補正の重みを抑える。完全なハイライト復元ではなく、色を失った領域を中立寄りに扱うヒューリスティック。
- 色行列後の符号付き・1.0を超えるリニアRGBを保持。明部の肩をリニア輝度へ適用し、輝度を基準とした色ベクトルにRGB共通の縮小率を掛けて表示可能な色域へ収めてからsRGB変換。ルック後も共通の色域圧縮を使い、独立したチャンネルクリップによる色相の変化を避ける。
- JPEGのSoftware/UserCommentへアプリ版、実際に採用したRAW/JPEG経路、highlight-v2、RAWの99.5%以上のサンプルを含む出力セルの割合、ルック設定を記録。ExifInterfaceは既存の同梱依存1.4.2を直接依存として明示しただけで、新しいライブラリは増えていない。
- EXIFの書き込みと同期まで成功した後にMediaStoreへ公開する。失敗時の入力保持・再試行と重複保存防止は維持。

## 確認範囲

既存の「テスト・動作検証は不要」の指定を引き継ぎ、テスト・lint・実機検証は実施せずAPKをビルドした。添付JPEGを加工した改善例は作っていない。元RAWがないため、この写真の再現像や、実機での改善の断定はできない。修正版で同じ条件を撮影して評価する必要がある。飽和して失われた看板の文字や色は戻せない。色付きLED等の極端な照明では、この近似補正も白へ寄せすぎる場合がある。
