# Cinema Camera — Android 写真版の試作

対象実機は **moto g66j 5G**。撮影後の編集操作を必要とせず、「明暗2・粒子G1」を基準に、実写のフィードバックで青みを抑え、フィルター効果を調整できる方向を自動適用し、JPEGを保存するための初期実装です。

**現在のバージョンは0.4.0（Android 15向け、デバッグ署名）です。** 上部の設定メニュー内にフィルター調整と保存を追加し、初期の青みを前版の45%へ抑えました。現像中の撮影、端末の向きに従う保存、保存フォルダを開くサムネイルボタンも引き続き使えます。フラッシュ、グリッド、水平器、連写、タップフォーカス、上下ドラッグの露出調整は引き続き使えます。この版はユーザーの指定によりテスト・動作検証を省略しています。0.1.0の検証記録は`docs/validation.md`に残しています。

## RAWを基本にする処理

1. CameraXが申告する出力形式を確認し、RAW+JPEG、RAW単独、JPEGの順でセッションを構築します。利用できない組み合わせは次へ進みます。
2. RAWを取得した場合、同じセンサー時刻のCaptureResultを対応付けます。黒レベル、白レベル、Bayer配列、ホワイトバランス、色変換行列、レンズシェーディング、露出ブーストを使います。
3. RAW16からシーンリニアsRGBを浮動小数点で生成します。初期版は2×2 Bayerのスーパーピクセル方式で、2つの緑を平均します。縦横の解像度はそれぞれおよそ半分です。
4. 浮動小数点テクスチャのままGPUへ渡し、明部の肩、sRGB変換、独自の階調・抑えた彩度・強めた冷たい影と中間調・G1の微粒子を適用します。**ルック適用前に8bit Bitmapへ落としてはいません。** 最終描画後に8bit JPEGへ変換します。
5. RAW取得・補正情報・現像・浮動小数点GPU処理のいずれかが利用できない場合はJPEGへフォールバックします。RAW+JPEGの同時取得が成功していれば、同じ撮影時刻のJPEGを使用します。
6. 同時取得のJPEGも使えない場合やRAW単独の取得失敗は、JPEGセッションへ切り替えて一度だけ再撮影します。この場合は別の撮影タイミングになり、画面に「撮り直しています…」と表示します。

撮影画面には現像方式やプロファイルを表示せず、自動で処理します。JPEGへの再撮影は一度までです。

## 撮影画面

- 背面カメラのルック付きプレビュー。撮影画像は`Pictures/CinemaCamera`へJPEGで保存。
- 上部にフラッシュ、三分割グリッド、水平器のON/OFF。設定は次回起動にも引き継ぎます。
- フラッシュは静止画撮影時に発光。フラッシュ非搭載のカメラでは操作を無効にします。
- 水平器は重力センサー（なければ加速度センサー）を使用し、水平に近づくと緑色になります。真下・真上に向ける場合は十字で表示します。
- プレビューをタップしてその位置へAF/AE。タップしたまま上へドラッグすると明るく、下へドラッグすると暗くなります。補正範囲と刻みは端末に従います。
- シャッターを長押し（約0.4秒）して連写。指を離すと次の撮影を止め、進行中の1枚は保存します。短い連打も最大4枚まで待ち行列に入ります。
- センサーからの取得と現像・保存を別のワーカーで実行。現像中でも次の露光・取得へ進みます。取得済み・取得中の写真は最大3枚とし、それ以上の短押しは撮影待ちになります。連写速度は端末の撮影と処理時間に依存します。
- RAWはカメラのバッファをキャッシュファイルへ退避し、バッファを閉じてから現像します。現像用のオフスクリーンEGLコンテキストはプレビューと独立し、写真アプリを開いた後も取得済み画像の保存を続けます。
- 画面は縦固定ですが、写真はシャッター時点の端末の向きを使用します。画面の自動回転がオフでも追従し、RAW/JPEGのどちらもピクセルを回転して保存します。
- グリッド・水平器・フォーカス枠は画面だけに表示し、写真には入りません。
- シャッター左に最新写真のサムネイル。タップすると外部のフォルダ対応アプリで`Pictures/CinemaCamera`を開きます。未対応の場合は、そのフォルダを初期位置にしたシステム画像選択画面を開き、選んだ画像を外部ビューアーへ渡します。Googleフォトには端末の特定フォルダを直接開く公開インテントがないため、Googleフォトでのアルバム直開きは保証しません。
- 上部の「設定」→「フィルター調整」から、全体の強さ・青み・彩度・コントラスト・粒子を調整できます。常時の撮影画面にはスライダーを出しません。
- 変更はプレビューに即時反映し、「保存」で次回起動に引き継ぎます。「キャンセル」・シートの外をタップ・戻る・保存前のアプリ中断では、変更前に戻ります。「初期値」はまずプレビューに反映し、保存するまで確定しません。
- 初期値は全体100%、青み45%、彩度86%、コントラスト100%、粒子100%。青み100%は0.3.0の強さ、コントラスト100%と粒子100%は従来の明暗2・G1を基準とします。全体0%ではルックを適用しません（RAWのベース現像は行います）。
- 各写真はシャッター時点のフィルター値を保持します。現像待ちの間に設定を変更しても、取得済み写真やJPEGへの再撮影に使う値は変わりません。
- 上部のプロファイル表示、元画像との比較ボタンはありません。
- 通信権限は宣言していません。写真のアップロード処理はありません。

プレビューと保存には同じ最終ルックのシェーダーを使います。ただし、プレビューは端末のISP処理済みYUV、RAW撮影結果は独自現像が入力です。**同じシェーダーを使うだけで両者の色・階調が一致するわけではなく、プレビューは近似です。** 実機の比較が必要です。

## ルックの根拠と限界

基準画像は`docs/look-reference.png`です。生成イメージであり、入力/出力の既知ペアからフィットしたカラープロファイルではありません。`look.frag`の数値は調整可能な初期値です。富士フイルムのシミュレーションや商用アプリを再現したものではありません。

- 明暗の分離を強めつつ、暗部のカーブにはゼロでない傾きを残します。
- 青みは暗部から中間調へ適用します。0.4.0の初期値は0.3.0の45%で、青みは設定内で0〜100%に調整できます。真っ黒と強いハイライトでは抑えます。肌を含む中間調も冷たくなるため、端末上で見え方を調整する余地があります。
- 粒子は細かな輝度成分。静止画/プレビュー間で画像に対する相対スケールを共有し、時間的に揺らさない初期設計です。
- 対応していれば端末の輪郭強調をオフにする要求を出しますが、処理の完全停止を保証するものではありません。
- 元の照明の方向や影の形を自動で作り替えません。

RAW初期現像は完全な写真現像エンジンではありません。高度なノイズ除去、ホットピクセル除去、エッジを考慮したフル解像度デモザイク、歪曲補正、複数フレーム合成、独自AWB、端末固有の色校正は未実装です。暗所で標準カメラより高画質になるとは限りません。

対応するRAWは、通常のRAW16 Bayer（RGGB/GRBG/GBRG/BGGR）で、補正情報と寸法が整合するものに限ります。未知の配列や欠落したメタデータを推測で埋めず、JPEGへ移ります。

プレビューは変換負荷を抑えるため最大約15fpsを目標にフレームを間引きます。保存画像の長辺は最大2560px。RAWは2×2方式のため、それより小さくなる場合があります。速度・発熱・メモリ使用量は実機で未測定です。

## ビルド

JDK 17以上、Android SDK Platform 36、SDK Build Tools 35.0.0を用意してください。Android Studioでこのディレクトリを開くか、`local.properties`にSDKパスを設定します。

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

```sh
./gradlew :app:assembleDebug :app:lintDebug
```

Windowsでは`gradlew.bat :app:assembleDebug :app:lintDebug`を使用します。

同梱ランチャーは通常のWrapper JARの代わりとなる小さなブートストラップです。Gradle 8.13を公式配布元から取得し、公開されたSHA256で検証して`.toolchain`に展開します。依存ライブラリの初回取得には通信が必要です。

APKは`app/build/outputs/apk/debug/app-debug.apk`です。配布用コピーはワークスペース直下の`cinema-camera-android15-v0.4.0-debug.apk`です。これはデバッグ用で、Playストア公開用の署名や設定は含みません。初回ビルド時にプロジェクト内の`.toolchain/debug.keystore`を作成します。同じ端末へ更新インストールするため、このキーは再作成せず保持してください。

## 0.1.0で実行した検証

```sh
sh tools/check-host.sh
```

JDK、Python標準ライブラリ、サーフェスレスEGL/GLESが利用できるLinuxで実行できます。ブラウザやAndroid SDK、ネットワークは不要です。

- RAW16の行/画素ストライド、バッファ位置、4種類のBayer配列。
- 黒レベル、WB、色行列、シェーディング、回転、浮動小数点精度。
- 不完全なRAW入力を拒否する条件。
- 画面内への画像配置、粒子の再現性と輝度成分。
- アプリと同じGLSLをEGL上でコンパイル・実行し、階調の単調性、暗部の分離、黒白の端点、影の青み、粒子、RGBAと上下方向を確認。
- Javaの構文解析、およびAndroid SDKを使った実際のコンパイルとAPK生成。
- Android lint（エラー0件、警告8件）、APK署名（v2）、targetSdk 35と同梱シェーダーの一致。

実機では、RAW対応申告→RAW取得→メタデータ整合→現像→JPEG保存を通した検証と、RAW/JPEGコールバックの順序・失敗時のフォールバック、アプリ復帰、撮影中の中断、容量不足を確認する必要があります。窓際/晴天/曇天/夜の実写で、肌・影・ハイライトの見え方を調整してください。

## 主なソース

- `MainActivity.java`: RAW/JPEG選択、撮影キュー、AF/AE、露出、フォールバックとライフサイクル。
- `CameraScreen.java` / `CameraOverlay.java`: 撮影操作、ジェスチャー、グリッドと水平器。
- `LookSettings.java` / `FilterSettingsDialog.java`: フィルター設定、ライブプレビュー、明示保存とキャンセル。
- `RawMetadata.java` / `CaptureMetadata.java`: 実機情報と撮影時刻の対応。
- `RawDeveloper.java` / `LinearPhoto.java`: RAW16から浮動小数点RGBへの初期現像。
- `LookSurface.java` / `PhotoRenderer.java` / `assets/look.frag`: 共通ルックと独立したプレビュー・写真用GPU描画。
- `PhotoStore.java`: MediaStoreのpending状態を使った新規JPEG保存。

## この環境での0.4.0 APK生成

Gradleが要求するローカルソケットの権限待ちを避け、既存の依存ライブラリ・リソースキャッシュとSDKを用いて`python tools/build-cached-apk.py`で生成しました。Javaコンパイル→D8→AAPT2→ZIP整列→既存デバッグキーでの署名を行います。この補助スクリプトには先行するGradleビルドのキャッシュが必要です。通常の環境では上記Gradleコマンドを使用できます。テスト・lint・実機動作検証はこの版では実施していません。
