# Cinema Camera — Android 写真版の試作

対象実機は **moto g66j 5G**。撮影後の編集操作を必要とせず、「明暗2・粒子G1」を基準に、実写のフィードバックで青みを抑え、フィルター効果を調整できる方向を自動適用し、JPEGを保存するための初期実装です。

**現在のバージョンは0.8.0（Android 15向け、デバッグ署名）です。** 撮影条件・撮影位置のEXIF記録と、端末が対応する範囲でのマニュアル露出・フォーカスを追加しました。RAWハイライトの補正とRGB共通の色域圧縮も維持しています。永続保管とJobSchedulerによるバックグラウンド保存・復旧は維持しています。露出表示の回転、フィルター調整と保存も引き続き使えます。現像中の撮影、端末の向きに従う保存、保存フォルダを開くサムネイルボタンも引き続き使えます。フラッシュ、グリッド、水平器、連写、タップフォーカス、上下ドラッグの露出調整は引き続き使えます。この版はユーザーの指定によりテスト・動作検証を省略しています。0.1.0の検証記録は`docs/validation.md`に残しています。

## RAWを基本にする処理

1. CameraXが申告する出力形式を確認し、RAW+JPEG、RAW単独、JPEGの順でセッションを構築します。利用できない組み合わせは次へ進みます。
2. RAWを取得した場合、同じセンサー時刻のCaptureResultを対応付けます。黒レベル、白レベル、Bayer配列、ホワイトバランス、色変換行列、レンズシェーディング、露出ブーストを使います。
3. RAW16からシーンリニアsRGBを浮動小数点で生成します。初期版は2×2 Bayerのスーパーピクセル方式で、2つの緑を平均します。縦横の解像度はそれぞれおよそ半分です。
4. RAWで飽和に近いサンプルを含む明るい領域には、撮影時WBゲインの範囲を見ながら中立色へ近づける近似補正を行います。失われた色や文字の復元ではなく、白い光源のマゼンタ化を抑える処理です。
5. 浮動小数点テクスチャのままGPUへ渡し、明部の肩、RGB共通の色域圧縮、sRGB変換、独自の階調・抑えた彩度・冷たい影と中間調・G1の微粒子を適用します。**ルック適用前に8bit Bitmapへ落としてはいません。** 最終描画後に8bit JPEGへ変換します。
6. RAW取得・補正情報・現像・浮動小数点GPU処理のいずれかが利用できない場合はJPEGへフォールバックします。RAW+JPEGの同時取得が成功していれば、同じ撮影時刻のJPEGを使用します。
7. 同時取得のJPEGも使えない場合やRAW単独の取得失敗は、JPEGセッションへ切り替えて一度だけ再撮影します。この場合は別の撮影タイミングになり、画面に「撮り直しています…」と表示します。

撮影画面には現像方式やプロファイルを表示せず、自動で処理します。JPEGへの再撮影は一度までです。

## 撮影画面

- 背面カメラのルック付きプレビュー。撮影画像は`Pictures/CinemaCamera`へJPEGで保存。
- 上部にフラッシュ、三分割グリッド、水平器のON/OFF。設定は次回起動にも引き継ぎます。
- フラッシュは静止画撮影時に発光。フラッシュ非搭載のカメラでは操作を無効にします。
- 水平器は重力センサー（なければ加速度センサー）を使用し、水平に近づくと緑色になります。真下・真上に向ける場合は十字で表示します。
- プレビューをタップしてその位置へAF/AE。タップしたまま上へドラッグすると明るく、下へドラッグすると暗くなります。露出スライダーと数値は縦・横・逆さの向きに追従し、ドラッグ方向も同じ向きに回転します。補正範囲と刻みは端末に従います。
- シャッターを長押し（約0.4秒）して連写。指を離すと次の撮影を止め、進行中の1枚は保存します。短い連打も最大4枚まで待ち行列に入ります。
- センサーからの取得と現像・保存を別のワーカーで実行。現像中でも次の露光・取得へ進みます。取得済み・取得中の写真は最大3枚とし、それ以上の短押しは撮影待ちになります。連写速度は端末の撮影と処理時間に依存します。
- RAW/JPEGと撮影時の設定はアプリの永続領域へ書き込み、ファイルとディレクトリを同期してからバックグラウンド処理へ渡します。キャッシュ領域は使いません。現像用のオフスクリーンEGLはプレビューと独立しています。
- 写真ごとのJobSchedulerジョブを永続登録し、ホーム移動・撮影画面終了・履歴からの終了・OSによるプロセス終了・端末再起動後も、OSが実行可能になった時に処理を継続／再開します。アプリのActivityを閉じてもジョブをキャンセルしません。
- 最終JPEGの書き込み、同期、MediaStoreでの公開確認が完了するまで元データを消しません。中断・容量不足等ではデータを残して指数バックオフで再試行します。写真IDに対応する固定ファイル名を使い、既存の未公開行を再利用することで再実行による二重保存を防ぎます。
- プロセス終了がデータ保管とジョブ登録の間に入った場合も、起動時と15分間隔の復旧ジョブで未登録分を再検出します。実際の実行時刻はOSの省電力・ジョブ制限に従います。
- 保存エラー時は「データ保管済み／自動再試行待ち」と表示し、上部の設定メニュー「未保存の写真を再試行」でも再試行できます。保管済みの写真は上限3枚に数え、保存が進むまで新たな撮影は待機します。
- 画面は縦固定ですが、写真はシャッター時点の端末の向きを使用します。画面の自動回転がオフでも追従し、RAW/JPEGのどちらもピクセルを回転して保存します。
- グリッド・水平器・フォーカス枠は画面だけに表示し、写真には入りません。
- シャッター左に最新写真のサムネイル。タップすると外部のフォルダ対応アプリで`Pictures/CinemaCamera`を開きます。未対応の場合は、そのフォルダを初期位置にしたシステム画像選択画面を開き、選んだ画像を外部ビューアーへ渡します。Googleフォトには端末の特定フォルダを直接開く公開インテントがないため、Googleフォトでのアルバム直開きは保証しません。
- 上部の「設定」→「フィルター調整」から、全体の強さ・青み・彩度・コントラスト・粒子を調整できます。常時の撮影画面にはスライダーを出しません。
- 変更はプレビューに即時反映し、「保存」で次回起動に引き継ぎます。「キャンセル」・シートの外をタップ・戻る・保存前のアプリ中断では、変更前に戻ります。「初期値」はまずプレビューに反映し、保存するまで確定しません。
- 初期値は全体100%、青み45%、彩度86%、コントラスト100%、粒子100%。青み100%は0.3.0の強さ、コントラスト100%と粒子100%は従来の明暗2・G1を基準とします。全体0%ではルックを適用しません（RAWのベース現像は行います）。
- 各写真はシャッター時点のフィルター値を保持します。現像待ちの間に設定を変更しても、取得済み写真やJPEGへの再撮影に使う値は変わりません。
- シャッター右の「撮影 AUTO/M」または上部設定の「撮影設定」から、M露出（シャッター速度・ISO）と独立したMFを操作できます。変更はプレビューへ反映し、「適用」で保存。キャンセル時は元へ戻ります。
- MANUAL_SENSOR、AE OFF、露光時間・感度・最大フレーム時間の範囲を確認し、非対応ならM露出を無効化します。AF OFFと最短フォーカス距離も確認し、固定焦点等ではMFを無効化します。絞りとWBは端末の自動／固定設定です。
- M露出ではフラッシュと通常のEV補正を無効化。MFではタップAFを行わず、AEがAUTOならタップ測光を維持します。長秒露光ではプレビューも低速になります。EXIFは指定値ではなく取得できた実際の撮影値を使います。
- 上部のプロファイル表示、元画像との比較ボタンはありません。
- 通信権限は宣言していません。写真のアップロード処理はありません。永続ジョブ用に`RECEIVE_BOOT_COMPLETED`、位置記録用に`ACCESS_FINE_LOCATION`・`ACCESS_COARSE_LOCATION`を宣言しています。バックグラウンドでカメラを起動しません。

保存継続の対象は**端末内へ取得・保管できた撮影データ**です。まだカメラから届いていないフレーム、撮影データを一度も書き込めないほどの容量不足、ストレージ故障・破損まで保証するものではありません。強制停止中はAndroidの仕様で実行できず、次回のアプリ起動後に復旧します。アプリのデータ消去・アンインストールは未保存データも削除します。RAW単独の現像に恒久的な非対応がある場合も元データは保持しますが、現像エンジンの修正等が必要になることがあります。

プレビューと保存には同じ最終ルックのシェーダーを使います。ただし、プレビューは端末のISP処理済みYUV、RAW撮影結果は独自現像が入力です。保存JPEGのEXIF Software/UserCommentには、アプリ版・RAW/JPEG経路・処理方式・RAW飽和付近のセルの割合・撮影時ルックを記録します。写真共有時にはEXIFが削除される場合があります。**同じシェーダーを使うだけで両者の色・階調が一致するわけではなく、プレビューは近似です。** 実機の比較が必要です。

## EXIFと撮影位置

- シャッター速度、ISO、F値、焦点距離、露出補正、露出モード、WB、フラッシュ、撮影日時・タイムゾーン、端末メーカー／機種を記録します。CaptureResultを画像のセンサー時刻で照合し、取れなければ元JPEGにある露出情報を引き継ぎます。取得できない値をスライダーの指定値で埋めません。
- 位置記録はOSの位置権限の許可が必要です。上部設定の「位置情報を記録」でOFFにできます。概算位置の許可でも動作します。バックグラウンド位置権限は要求せず、カメラ画面が前面の間だけ更新を受けます。
- 撮影要求時の測位をスナップショットし、60秒を超えた値は使いません。シャッター下にもON／測位待ち／OFFの状態を表示します。測位できなければ位置情報なしで撮影を続けます。標準GPSタグに緯度経度、取得できた高度・水平精度、測位のUTC日時と方法を記録します。
- 撮影時の位置と撮影条件は画像と一緒に永続保管し、後からバックグラウンド現像しても処理時点の場所へ置き換えません。座標をUserCommentへ重複記録しません。位置OFFはそれ以降の撮影に適用し、既存画像のGPSは変更しません。
- 撮影直後や屋内・端末の位置設定OFF等では測位が間に合わないことがあります。共有アプリやOSはEXIF／位置情報を除去する場合があります。

## ルックの根拠と限界

基準画像は`docs/look-reference.png`です。生成イメージであり、入力/出力の既知ペアからフィットしたカラープロファイルではありません。`look.frag`の数値は調整可能な初期値です。富士フイルムのシミュレーションや商用アプリを再現したものではありません。

- 明暗の分離を強めつつ、暗部のカーブにはゼロでない傾きを残します。
- 青みは暗部から中間調へ適用します。0.4.0の初期値は0.3.0の45%で、青みは設定内で0〜100%に調整できます。真っ黒と強いハイライトでは抑えます。肌を含む中間調も冷たくなるため、端末上で見え方を調整する余地があります。
- 粒子は細かな輝度成分。静止画/プレビュー間で画像に対する相対スケールを共有し、時間的に揺らさない初期設計です。
- 対応していれば端末の輪郭強調をオフにする要求を出しますが、処理の完全停止を保証するものではありません。
- 元の照明の方向や影の形を自動で作り替えません。

RAW初期現像は完全な写真現像エンジンではありません。高度なノイズ除去、ホットピクセル除去、エッジを考慮したフル解像度デモザイク、歪曲補正、複数フレーム合成、独自AWB、端末固有の色校正は未実装です。暗所で標準カメラより高画質になるとは限りません。

対応するRAWは、通常のRAW16 Bayer（RGGB/GRBG/GBRG/BGGR）で、補正情報と寸法が整合するものに限ります。未知の配列や欠落したメタデータを推測で埋めず、JPEGへ移ります。

プレビューは変換負荷を抑えるため最大約15fpsを目標にフレームを間引きます。保存画像の長辺は最大2560px。RAWは2×2方式のため、それより小さくなる場合があります。速度・発熱・メモリ使用量は実機で未測定です。

## ビルド

JDK 17以上、Android SDK Platform 36、SDK Build Tools 35.0.0を用意してください。Android Studioでこのディレクトリを開くか、`local.properties`にSDKパスを設定します。

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

```sh
./gradlew :app:assembleDebug :app:lintDebug
```

Windowsでは`gradlew.bat :app:assembleDebug :app:lintDebug`を使用します。

同梱ランチャーは通常のWrapper JARの代わりとなる小さなブートストラップです。Gradle 8.13を公式配布元から取得し、公開されたSHA256で検証して`.toolchain`に展開します。依存ライブラリの初回取得には通信が必要です。

APKは`app/build/outputs/apk/debug/app-debug.apk`です。配布用コピーはワークスペース直下の`cinema-camera-android15-v0.8.0-debug.apk`です。これはデバッグ用で、Playストア公開用の署名や設定は含みません。初回ビルド時にプロジェクト内の`.toolchain/debug.keystore`を作成します。同じ端末へ更新インストールするため、このキーは再作成せず保持してください。

## 0.1.0で実行した検証

```sh
sh tools/check-host.sh
```

JDK、Python標準ライブラリ、サーフェスレスEGL/GLESが利用できるLinuxで実行できます。ブラウザやAndroid SDK、ネットワークは不要です。

- RAW16の行/画素ストライド、バッファ位置、4種類のBayer配列。
- 黒レベル、WB、色行列、シェーディング、回転、浮動小数点精度。
- 不完全なRAW入力を拒否する条件。
- 画面内への画像配置、粒子の再現性と輝度成分。
- アプリと同じGLSLをEGL上でコンパイル・実行し、階調の単調性、暗部の分離、黒白の端点、影の青み、粒子、RGBAと上下方向を確認。
- Javaの構文解析、およびAndroid SDKを使った実際のコンパイルとAPK生成。
- Android lint（エラー0件、警告8件）、APK署名（v2）、targetSdk 35と同梱シェーダーの一致。

実機では、RAW対応申告→RAW取得→メタデータ整合→現像→JPEG保存を通した検証と、RAW/JPEGコールバックの順序・失敗時のフォールバック、アプリ復帰、撮影中の中断、容量不足を確認する必要があります。窓際/晴天/曇天/夜の実写で、肌・影・ハイライトの見え方を調整してください。

## 主なソース

- `MainActivity.java`: RAW/JPEG選択、撮影キュー、AF/AE、露出、フォールバックとライフサイクル。
- `CameraScreen.java` / `CameraOverlay.java`: 撮影操作、ジェスチャー、グリッドと水平器。
- `ManualSettings.java` / `ManualSettingsDialog.java`: 端末の対応範囲に従うM露出・MFと設定の保存。
- `CaptureExif.java` / `PhotoLocation.java`: 実撮影値、時刻、前面で取得する撮影位置。
- `LookSettings.java` / `FilterSettingsDialog.java`: フィルター設定、ライブプレビュー、明示保存とキャンセル。
- `RawMetadata.java` / `CaptureMetadata.java`: 実機情報と撮影時刻の対応。
- `RawDeveloper.java` / `LinearPhoto.java`: RAW16から浮動小数点RGBへの初期現像。
- `LookSurface.java` / `PhotoRenderer.java` / `assets/look.frag`: 共通ルックと独立したプレビュー・写真用GPU描画。
- `PhotoStore.java`: 固定写真IDによるMediaStoreの未公開行再利用、同期、公開確認。
- `PendingPhotoStore.java`: 永続領域のRAW/JPEG・メタデータ・撮影設定・完了状態の原子的な保存。
- `PhotoSaveJobService.java` / `SaveScheduler.java`: 永続バックグラウンドジョブ、1枚ずつの現像、再試行。
- `CameraApplication.java` / `SaveRecoveryService.java`: プロセス再作成時と定期的な未保存データの再検出。
